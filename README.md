# Москва | Возможности

Telegram-канал городских возможностей Москвы: работа, IT, стажировки, образование, гранты, события, городские инициативы, права и льготы.

**Архитектура:** Cloudflare Worker + Cloudflare D1 + Cloudflare Workers AI + Telegram Bot API.

Канал: [@moscow_opportunities](https://t.me/moscow_opportunities)

## Автоматический pipeline

1. Worker забирает RSS и Atom из активных источников.
2. Ссылки нормализуются, дубли отсекаются по уникальному URL.
3. Каждый материал оценивает **ИИ**: реальная ли это возможность, какая категория, география и есть ли признаки закрытия.
4. Перед публикацией Worker загружает исходную страницу, а ИИ повторно проверяет её содержимое и актуальность.
5. Ручного одобрения, отклонения и ручной публикации нет. Если ИИ недоступен или не уверен, материал не публикуется; эвристического fallback нет.
6. Автопубликация — максимум один пост за запуск и три за UTC-сутки, только свежие материалы за 36 часов. Старая очередь не публикуется массово.

## ИИ-модерация

- Используется Cloudflare Workers AI через binding `AI`; внешний API-ключ не нужен.
- ИИ определяет релевантность, категорию, географию (Москва/МО, remote, другой регион, неизвестно) и признаки закрытия.
- Старые записи со статусом pending перепроверяются ИИ партиями до 20 записей за запуск.
- Ошибки ИИ не приводят к публикации без проверки.
- ИИ может ошибаться; исходная ссылка сохраняется.

## Команды

- `/myid` — Telegram ID.
- `/help` — справка.
- `/collect` — сбор и ИИ-отбор.
- `/queue` — последние одобренные ИИ материалы.
- `/feeds` — активные RSS-источники.
- `/addfeed Название | https://example.com/rss` — добавить источник.
- `/stats` — статистика.

## Структура

- `worker/src/index.js` — Worker, RSS/Atom, ИИ-модерация, форматирование, Telegram.
- `worker/wrangler.toml` — Worker, D1 и Workers AI bindings, hourly Cron.
- `worker/schema.sql` — справочная схема; не выполнять на production D1.
- `worker/test/worker.test.js` — тесты.

## Секреты и deployment

Cloudflare Worker Secrets: `BOT_TOKEN`, `WEBHOOK_SECRET`, `SETUP_SECRET`. Workers AI использует binding `AI`, отдельный ключ не нужен.

Никогда не коммитьте токены, секреты, OAuth-файлы или пароли. Изменения в GitHub не обновляют production Worker автоматически: после проверки изменений deploy выполняется отдельно через Wrangler. Не пересоздавать существующую D1 и не выполнять на ней `schema.sql`.
