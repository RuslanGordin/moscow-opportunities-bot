# Москва | Возможности

Telegram-канал городских возможностей Москвы: работа, IT, стажировки, образование, гранты, события, городские инициативы, права и льготы.

**Архитектура:** Cloudflare Worker + Cloudflare D1 + Telegram Bot API.

Канал: [@moscow_opportunities](https://t.me/moscow_opportunities)

## Текущий pipeline

1. Worker забирает RSS и Atom из активных источников по расписанию и команде `/collect`.
2. Материалы нормализуются, ссылки очищаются от tracking-параметров, дубли отсекаются по уникальному URL.
3. Проверяются заголовок, категория, география и дата публикации.
4. География: Москва/Московская область; удалённые возможности — только при наличии признака удалённой работы, а для явно указанного другого города требуется формулировка о доступности из любого региона.
5. Уровень Junior/Middle/Senior/Lead не является самостоятельной причиной отклонения. Он извлекается для редакционной карточки, если указан в тексте.
6. Новые подходящие материалы получают статус `approved`; публикация в канал остаётся отдельным ручным действием `/publish ID`.
7. Старая очередь обрабатывается ограниченными пакетами D1.

## Важные ограничения

- Текущая система использует прозрачные эвристики, а не AI-проверку полного текста страницы.
- RSS-описание может не содержать зарплату, требования или срок закрытия. Бот не должен выдумывать отсутствующие сведения.
- Без отдельной проверки страницы источника нельзя гарантировать, что вакансия ещё открыта.
- Географию и доступность remote нужно подтверждать текстом источника; сомнительные случаи лучше отклонять, чем выдавать за московские.
- Набор подключённых источников определяет охват. Не добавляйте непроверенные RSS-кандидаты в production автоматически.
- Автоматический отбор не равен автоматической публикации.

## Команды

- `/myid` — Telegram ID.
- `/help` — справка.
- `/collect` — сбор и отбор.
- `/queue` — последние одобренные материалы.
- `/publish ID` — публикация одобренного материала.
- `/feeds` — активные RSS-источники.
- `/addfeed Название | https://example.com/rss` — добавить источник.
- `/stats` — статистика статусов.

## Структура

- `worker/src/index.js` — Worker, RSS/Atom, отбор, форматирование, Telegram.
- `worker/wrangler.toml` — Worker, D1 binding и hourly Cron.
- `worker/schema.sql` — справочная схема существующей базы, не production migration.
- `worker/test/worker.test.js` — тесты.
- `worker/README.md` — эксплуатационные ограничения.

## Секреты

Cloudflare Worker Secrets: `BOT_TOKEN`, `WEBHOOK_SECRET`, `SETUP_SECRET`.
Переменные: `CHANNEL_ID`, `ADMIN_IDS`.

Никогда не коммитьте токены, секреты, OAuth-файлы или пароли.

## Проверка и deployment

Тесты запускаются через GitHub Actions. Изменения в GitHub не обновляют production Worker автоматически. Production deploy выполняется отдельно после проверки PR. Существующую D1 нельзя пересоздавать или накатывать на неё справочную `schema.sql`.
