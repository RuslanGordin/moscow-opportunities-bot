# Москва | Возможности

Telegram-бот для сбора, модерации и публикации вакансий, стажировок и мероприятий для студентов и начинающих специалистов в Москве.

**Текущая архитектура:** Cloudflare Worker + Cloudflare D1 + Telegram Bot API. Старый Python MVP больше не является актуальным способом запуска проекта.

Канал: [@moscow_opportunities](https://t.me/moscow_opportunities)

## Как работает

1. Worker получает RSS-материалы из активных источников.
2. Новые записи сохраняются в D1; повторные ссылки не добавляются.
3. Очевидные вакансии уровня Senior/Middle/Lead и предложения с явно указанным требованием от двух лет опыта отфильтровываются.
4. Остальные материалы попадают в очередь на ручную проверку.
5. Администратор одобряет или отклоняет материалы.
6. Только одобренные материалы публикуются в Telegram-канале вручную.

Автоматический сбор предусмотрен по часовому Cron Trigger. Настройка расписания находится в `worker/wrangler.toml`; она начнёт действовать в Cloudflare после развёртывания этой версии Worker.

## Команды администратора

- `/myid` — показать Telegram ID.
- `/help` — справка.
- `/collect` — запустить сбор вручную.
- `/queue` — показать последние материалы на проверке.
- `/approve ID` — одобрить материал.
- `/reject ID` — отклонить материал.
- `/publish ID` — опубликовать одобренный материал.
- `/feeds` — показать активные RSS-источники.
- `/addfeed Название | URL` — добавить RSS-источник.
- `/stats` — статистика очереди.

Административные команды доступны только ID из `ADMIN_IDS`.

## Структура проекта

- `worker/src/index.js` — обработчик Telegram webhook, RSS-сбор, модерация и публикация.
- `worker/wrangler.toml` — конфигурация существующего Cloudflare Worker, D1 binding и Cron Trigger.
- `worker/schema.sql` — справочная схема таблиц. Это не миграция.
- `worker/test/worker.test.js` — автоматические тесты.
- `worker/README.md` — заметки по Worker и его конфигурации.

## Секреты и безопасность

В Cloudflare Worker Secrets должны быть заданы:

- `BOT_TOKEN` — токен Telegram-бота.
- `WEBHOOK_SECRET` — секрет проверки Telegram webhook.
- `SETUP_SECRET` — секрет защиты служебного endpoint настройки webhook.

Обычные переменные Worker:

- `CHANNEL_ID` — целевой Telegram-канал.
- `ADMIN_IDS` — список Telegram ID администраторов через запятую.

**Не добавляйте токены, секреты, OAuth-файлы или пароли в Git, задачи и переписку.** Бот должен иметь в канале только необходимые права, прежде всего право публикации сообщений.

## Проверки и развёртывание

Тесты запускаются в GitHub Actions при изменениях Worker. Изменения исходников в GitHub сами по себе не обновляют работающий Worker: для этого требуется отдельное осознанное развёртывание в Cloudflare.

Production D1 уже содержит рабочие таблицы. Не запускайте `worker/schema.sql` на production и не пересоздавайте базу ради обновления кода.
